hub — the OctoSense app hub command (ADR 0003)

  hub keygen <path>                     make a signing key, print its public half
  hub pubkey <key file>                 print a key's public half
  hub certify --anchor <f> --working <f>   anchor certifies a working key
  hub stamp <bundle>                    write the bundle's digest into its manifest
  hub sign-manifest <bundle> --key <f> --key-id <id>
  hub check <bundle> [--catalog <f> --anchor <hex>] [--allow-unsigned] [--publisher-key id=hex]
  hub test <bundle> [--validator <executable>] [--json] [check flags]
  hub admin publish <bundle> --catalog <f> --state-dir <private directory>
              --expected-sequence <n> --idempotency-key <request>
              --anchor <hex> --key <f> --anchor-cert <hex>
              --publisher <id> --publisher-key id=hex
              --reviewed-by <operator> --review-id <decision>
              [--repo <url>] [--commit <sha>] [--validator <executable>]
  hub admin withdraw <app> --version <v> --reason <text>
              --catalog <f> --state-dir <private directory>
              --expected-sequence <n> --idempotency-key <request>
              --anchor <hex> --key <f> --anchor-cert <hex>
              (retains released identity/history; destructive remove is disabled)
  hub scan <bundle> [--catalog <f> --anchor <hex>] [--reviewer <cmd>] [--packet <out.json>]
  hub verify <catalog> --anchor <hex>
  hub admin renew --catalog <f> --state-dir <private durable directory>
              --expected-sequence <n> --idempotency-key <request>
              --anchor <hex> --key <f> --anchor-cert <hex>

Publication requires recorded operator review and creates immutable artifacts,
pack.json and validation.json before atomically signing/swapping the catalog.
Run reviewer commands separately with scan; --reviewer/--reviewed are not publish
flags. publish/withdraw remain operator aliases for admin publish/withdraw.
State must be outside the public catalog directory, on the same filesystem.

check --json emits structural findings; test --json adds native validation
with structured failures and evidence on success. Both accept local
--allow-unsigned checks. Build app-validator beside hub, or provide a trusted
operator-selected worker with --validator. Publication requires native evidence
and writes <artifact>.validation.json. Worker limits: 10 seconds, bounded output,
256 MiB Rust allocations; Unix runner required. Visual/device review is separate.

check is the gate: a publisher runs it before submitting, the hub runs the
same code after. publish re-runs it, copies the bundle into the artifact
store and signs the catalog.

Public releases must be signed. --allow-unsigned is only for local checks.
An existing catalog requires --anchor to authenticate its publisher history.
V1 publisher IDs and manifest signature key IDs must match; a supplied key
cannot replace a key already registered in the authenticated catalog.
